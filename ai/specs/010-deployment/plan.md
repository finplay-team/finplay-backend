- PRD: `ai/prd.md` §3 — 배포 관련 현황은 있으나 이 작업 전용 요구사항 ID는 없음

## 설계

백엔드 배포 권한과 분리된 프론트 전용 IAM 역할을 Terraform에 선언한다. 역할의 신뢰 정책은 이미 구성된 GitHub OIDC 제공자를 참조하고, GitHub Actions audience와 현재 프론트 배포 저장소·브랜치의 subject가 모두 일치할 때만 역할 수임을 허용한다. subject 형식은 현재 OIDC 구성의 규칙을 따르며, 실제 배포 브랜치는 기존 프론트 워크플로에서 확인한 뒤 고정한다.

권한 정책은 기존 워크플로가 실행하는 S3 동기화의 명령·옵션에서 필요한 작업을 도출한다. 버킷 조회가 필요하면 버킷 리소스에만, 객체 업로드·삭제가 필요하면 기존 대상 객체 범위에만 권한을 나눠 부여한다. `--delete`가 실제 사용될 때에만 삭제 권한을 허용한다. ACL·객체 읽기·CloudFront·DNS 권한 등은 현재 동기화가 필요로 한다는 근거가 없는 한 추가하지 않는다. 실제 리소스 식별자는 문서에 기재하지 않는다.

기존 OIDC 제공자, 정적 사이트 버킷, CloudFront, DNS 및 프론트 앱·워크플로는 수정하지 않는다. 프론트 워크플로 확인은 배포 브랜치와 권한 집합을 판정하기 위한 읽기 전용 입력이다.

## 입력 명세

| 입력 | 출처 | 검증 기준 |
|---|---|---|
| 프론트 배포 저장소·브랜치 | 현재 프론트 GitHub Actions 워크플로 | 배포 트리거가 사용하는 단일 저장소·브랜치만 subject에 허용 |
| GitHub OIDC 제공자 | 기존 계정·Terraform 구성 | 기존 제공자를 참조하고 중복 생성·변경하지 않음 |
| S3 동기화 목적지·대상 경로 | 현재 프론트 워크플로 설정 | 실제 동기화 대상에만 객체 권한 적용; 식별자는 문서·로그에 출력하지 않음 |
| 동기화 작업·옵션 | 현재 `aws s3 sync` 명령 | 필요한 작업만 허용; `--delete`가 있을 때만 삭제 허용 |

## 인프라 모델

| 구성 | 의도 |
|---|---|
| 프론트 전용 IAM 역할 | 기존 OIDC 제공자를 통한 GitHub Actions 임시 역할 수임 |
| AssumeRole 신뢰 정책 | audience와 프론트 저장소·배포 브랜치 subject를 함께 제한 |
| S3 권한 정책 | 현재 동기화에 필요한 버킷 수준·객체 수준 작업만 허용 |

API, 애플리케이션 데이터 모델, 데이터베이스 변경은 없다.

## 테스트 계획
- 정적 검사: 변경 후 Terraform `fmt -check` 및 `validate`를 실행한다.
- 계획 검토: Terraform plan에서 역할·정책 외 리소스 변경이 없고, 기존 OIDC 제공자·버킷·CloudFront·DNS가 변경되지 않는지 확인한다.
- 권한 검토: 신뢰 정책이 지정 저장소·배포 브랜치만 허용하고, 정책의 각 S3 작업이 기존 동기화 옵션으로 정당화되는지 확인한다. 다른 저장소·브랜치 subject는 거부돼야 한다.
- 통합 확인: 워크플로 파일을 변경하지 않고 기존 프론트 배포 작업으로 S3 동기화가 되는지 확인한다. 실행 전 필요한 AWS 반영·GitHub 설정 범위를 확인한다.
