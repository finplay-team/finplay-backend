# ADR-0031: EC2 CloudWatch Agent를 제거하고 기본 지표·애플리케이션 로그를 유지한다

- 상태: 승인됨
- 날짜: 2026-09-14
- 관계: [ADR-0030](0030-rolling-deploy-multi-instance.md)의 CloudWatch Agent 관련 결정을 이 ADR이 대체한다. ADR-0030의 다중 인스턴스·롤링 배포·기본 CloudWatch 지표·Docker `awslogs`·SSM 초기화에 관한 나머지 결정은 그대로 유효하다.

## 맥락

ADR-0030은 EC2에 CloudWatch Agent를 설치해 기본 EC2 지표에 없는 메모리·디스크 사용률을 수집하고, 컨테이너 로그는 Docker `awslogs` 드라이버로 CloudWatch Logs에 보내는 관측성 구성을 결정했다. 그러나 EC2마다 별도 에이전트를 설치·기동하고 에이전트 전용 권한을 부여하는 운영·권한 범위가 현재 배포 규모에 비해 크다.

애플리케이션 로그와 인스턴스 초기화 경로는 에이전트와 독립적이다. Docker `awslogs`는 컨테이너 표준 출력·표준 에러를 CloudWatch Logs로 보내고, SSM과 `/opt/finplay/refresh-env.sh`는 배포 시 환경변수를 초기화한다.

## 결정

### 1. EC2 CloudWatch Agent를 제거한다

EC2 CloudWatch Agent를 메모리·디스크·로그 수집 목적으로 설치하거나 실행하지 않는다. 에이전트 전용 관리형 IAM 정책도 EC2 인스턴스 역할에서 제거한다.

### 2. 기본 지표와 애플리케이션 로그는 유지한다

- EC2 기본 지표를 유지한다.
- ALB 기본 지표를 유지한다.
- CloudFront 기본 지표를 유지한다.
- Docker `awslogs` 애플리케이션 로그 수집을 유지한다.
- SSM 권한과 SSM을 통한 명령 실행을 유지한다.
- `refresh-env.sh`를 통한 SSM Parameter Store 기반 환경변수 초기화를 유지한다.

Docker 로그 전송에 필요한 CloudWatch Logs 권한은 기존 인스턴스별 로그 그룹을 대상으로만 부여한다. `logs:DescribeLogStreams`는 로그 그룹 ARN에만 허용하고, `logs:CreateLogStream`·`logs:PutLogEvents`는 해당 로그 그룹의 로그 스트림 ARN 패턴에만 허용한다.

## 결과

### 좋은 점

- EC2의 에이전트 설치·기동·설정 관리가 사라져 배포 구성이 단순해진다.
- 에이전트 전용 관리형 정책을 제거하고 Docker 로그 전송 권한만 필요한 로그 리소스로 제한할 수 있다.
- 애플리케이션 로그, 배포 명령 실행, 환경변수 초기화 경로는 유지되므로 기본 운영·장애 확인 흐름은 계속 사용할 수 있다.

### 관측성 손실과 대응

- 메모리 사용률과 디스크 사용률의 CloudWatch 커스텀 지표가 사라진다. 따라서 해당 지표에 의존하는 알람·대시보드는 제공하지 않는다.
- 대응으로 EC2·ALB·CloudFront 기본 지표와 Docker `awslogs` 애플리케이션 로그를 유지한다.
- 인스턴스 명령 실행과 환경 재초기화는 SSM 및 `refresh-env.sh`를 계속 사용한다.
- 메모리·디스크 관측을 다시 도입할 필요가 생기면 별도 ADR에서 수집 방식과 비용·권한 범위를 다시 결정한다.

## 대안과 기각 사유

**(a) CloudWatch Agent를 그대로 유지한다**

메모리·디스크 지표를 계속 얻을 수 있지만, EC2별 에이전트 운영과 전용 권한이 필요하다. 현재 유지하기로 한 기본 지표·애플리케이션 로그·SSM 경로로 운영에 필요한 최소 관측성을 확보할 수 있으므로 기각한다.

**(b) 다른 커스텀 메트릭 수집기를 즉시 도입한다**

메모리·디스크 손실을 줄일 수 있지만 수집기 선택·운영·권한 설계가 추가로 필요하다. 이번 변경 범위에는 대체 수집기를 도입하지 않고, 필요성이 확인될 때 별도 결정한다.
